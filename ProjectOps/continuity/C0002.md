### Revisión del antiguo bloqueo Node 24

README documentaba que Node 24 se rechazó porque `better-sqlite3` 11 podía carecer del prebuild Windows necesario y caer a `node-gyp`.

La primera hipótesis fue usar `better-sqlite3` 13 por su migración a N-API y soporte Node >=22. Esta hipótesis quedó **falsada para Windows x64 Node 24** por ejecución real:
- CI run `34781052095`, job `103788015717`;
- `better-sqlite3@13.0.3` cayó a `node-gyp rebuild` durante `pnpm install --frozen-lockfile`;
- el runner Windows no pudo completar la compilación y el job falló antes de typecheck/tests;
- por tanto `better-sqlite3` 13 NO puede acreditarse como instalación normal de ABOS en esa lane.

La auditoría upstream identificó una alternativa de menor riesgo: `better-sqlite3@12.12.0`.
- declara soporte Node `20.x || 22.x || 23.x || 24.x || 25.x || 26.x`;
- conserva `prebuild-install || node-gyp rebuild --release`;
- su release publica artefactos prebuilt, incluida familia Windows x64;
- es la última release 12.x inmediatamente anterior al cambio N-API de v13.

Decisión `DECISION_READY` revisada:
- retirar Node 20 EOL;
- mantener Node 22 como default/recommended;
- validar Node 24 como segunda LTS soportada;
- usar `better-sqlite3` 12.12.0 como candidato de compatibilidad Windows/Node 24 en vez de forzar v13 o instalar toolchain C++ al usuario.
