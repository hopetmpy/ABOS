### Grafo authority / producers / consumers

- Generic capability authority: `CapabilityRegistry`, único y en memoria.
- Producers: built-in/runtime tool definitions, installed-tool inventory, loaded skills y `EnvironmentSnapshot.capabilities`.
- Evidence-rich producers: environment providers mediante `inspect()`; availability/evidence/observedAt se proyectan al registry.
- Consumers: `CapabilityResolver`, `resolve_capability`, planner/orchestrator y paths de resolution.
- Claims paralelos auditados: system prompt, CLI/status y list surfaces.
- Persistence: generic registry no durable; installed tools y skills son inventory durable y no pueden elevar readiness tras restart sin evidencia actual.
- Environment resource lifecycle permanece separado y no compite como segunda generic authority.

5. CONFIRMADO — persisted skills necesitaban revalidación tras restart.

7. CONFIRMADO — child-balance UNKNOWN debía preservarse según P-003.

9. SCOPE PRESERVADO — P-015 conserva MCP real; P-008 neutraliza el false-success sin adelantar P-015.
10. FALSADO — `loadInstalledTools()` NO cargaba disabled rows; DB ya aplica `enabled = 1`. La corrección real es enabled/installed != verified readiness.
11. NO_CHANGE — `EnvironmentSelector` permite `degraded` con penalización. No se cambió porque degraded puede seguir siendo operacional; P-008 no demuestra que deba colapsarse a unavailable.

### Decisión

Clasificación dominante: **EXTEND + UNIFY + CORRECT**, no CREATE.

- Mantener `CapabilityRegistry` como única generic authority.
- Lifecycle/evidence/authority/temporalidad explícitos.
- `VERIFIED_AVAILABLE` sólo con evidence + `observedAt` válidos.
- `available` legacy como proyección derivada.
- Inventory/configuration no se eleva a readiness.
- Environment snapshots entran por `registerEnvironmentSnapshot()`.
- Resolver preserva UNKNOWN / UNAUTHORIZED / PROHIBITED.
- P-008 no preimplementa P-014/P-015.
