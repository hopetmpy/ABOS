## Hallazgos verificables

1. `ModelRegistry.initialize()` can disable a dynamic model from a provider present in the static baseline solely because the model ID is absent from that baseline.
2. Existing `dynamic-model-provider-preservation.test.ts` protects dynamically added providers but explicitly expects an unknown OpenAI sibling model to be disabled; this contradicts P-019 open dynamic catalog semantics.
3. `InferenceRouter` already has connection-model compatibility hooks, budget, timeout, attempt evidence and outcome evidence. A new adaptive router would duplicate authority.
4. Codex already supplies dynamic catalog metadata including supported/default reasoning efforts; adaptive inference can build on this rather than inventing a second catalog.
5. Legacy `ProviderRegistry` owns a separate hard-coded provider/model/fallback matrix.
6. `UnifiedInferenceClient.chat()` can continue across provider candidates after retryable errors, creating silent cross-provider switching that violates the plan boundary unless an explicit replan/authority transition owns it.
7. Production consumers of the legacy client are not yet proven; source must not be deleted based only on architectural suspicion.
