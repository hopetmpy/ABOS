## Findings iniciales verificables

### F1 — runtime principal usa stack cognitivo básico

`src/agent/loop.ts`:
- importa `MemoryRetriever` desde `src/memory/retrieval.ts`;
- instancia ese retriever dentro del pre-turn memory retrieval;
- formatea sus resultados y luego construye prompt con `buildContextMessages()` de `src/agent/context.ts`.

Por tanto, existencia/test de módulos avanzados no equivale a runtime authority activa.

### F2 — ContextManager avanzado existe pero está desconectado

`src/memory/context-manager.ts` ya implementa:
- token counter con BPE/fallback y bounded cache;
- model-aware prompt budget;
- preservación de system/todo/recent turns;
- memories/events/task spec bajo budget;
- compression/utilization/recommendation;
- compacted event references.

Tiene suite dedicada en `src/__tests__/memory/context-manager.test.ts`, pero no gobierna `AgentLoop`.

### F3 — EnhancedRetriever existe pero está desconectado

`src/memory/enhanced-retriever.ts`:
- extiende `MemoryRetriever`;
- agrega query expansion, recency/frequency/confidence/task-affinity/category scoring;
- budget dinámico y feedback/precision;
- usa `KnowledgeStore` durable.

Tiene suite dedicada, pero el loop usa directamente `MemoryRetriever` básico.

### F4 — KnowledgeStore es closed-world en app, no en SQLite

`src/memory/knowledge-store.ts` define `KnowledgeCategory` como cinco literals y `toKnowledgeEntry()` lanza error ante otra categoría.

Persistence `knowledge_store.category` es `TEXT`; no existe CHECK enum que obligue esas cinco categorías. El cierre es una restricción de app/types, no una necesidad durable.

### F5 — category inference puede invisibilizar knowledge futuro

`EnhancedRetriever` infiere sólo categorías conocidas y, cuando encuentra categorías, busca por ellas como filtro. Un nuevo label válido puede persistirse pero quedar fuera de una búsqueda categorizada. Las categorías existentes deben tratarse como hints/tags compatibles, no universo máximo.

### F6 — authorities adyacentes ya existen

- P-013 Evidence Fabric posee correlation/evidence causal.
- `src/intelligence/` posee Adaptive Path planning/evidence/replan concerns.
- `src/skills/` posee skill registry/discovery/lifecycle; P-021 posee Skill Evolution.
- `agent-context-aggregator.ts` agrega estado amplio del actor/recursos; no se fusiona con prompt assembly sólo por nombre.

P-020 debe conectarse a estas authorities, no duplicarlas.

## Riesgos a falsar antes de source

1. cablear `ContextManager` podría perder tool-call protocol/message ordering preservado por `buildContextMessages`;
2. `EnhancedRetriever` podría sustituir memory tiers por sólo KnowledgeStore si se usa de forma incorrecta;
3. abrir categorías sin corregir filtros puede convertir el type fix en knowledge invisible;
4. crear relation graph nuevo podría duplicar `relationship_memory`, semantic memory o Evidence Fabric;
5. usar global feedback state de EnhancedRetriever puede introducir cross-agent/session contamination;
6. budgets fijos del componente avanzado no deben reducir capacidad existente ni ignorar model context real;
7. restart debe reconstruir activación desde durable state sin requerir in-memory singleton state.
