## Findings y discriminación

### F1 — el runtime principal tenía una desconexión cognitiva real

Antes de P-020, `src/agent/loop.ts` recuperaba los cinco memory tiers con `MemoryRetriever` y construía el prompt con `buildContextMessages()`, mientras `ContextManager` y `EnhancedRetriever` existían y tenían tests pero no gobernaban el main turn path. Existencia de source/test no era evidencia de runtime wiring.

### F2 — `MemoryRetriever` es primitive reutilizable, no duplicado prescindible

`src/memory/retrieval.ts` agrega con budget:
- working memory;
- episodic memory;
- semantic memory;
- procedural memory;
- relationship memory.

`EnhancedRetriever.retrieveScored()` obtiene candidates de `knowledge_store`; sustituir completamente `MemoryRetriever` habría perdido los cinco tiers. Se conserva como primitive y `EnhancedRetriever` queda como activador/scorer suplementario.

### F3 — `ContextManager` ya era la mejor authority de assembly

`src/memory/context-manager.ts` ya poseía tokenización real/fallback, cache acotado, model context window, budget, recent-turn preservation, tool-result truncation, utilization y compactación. P-020 lo extendió para reservar tail obligatorio y múltiples memory blocks, manteniendo pending input al final.

Adversarial review encontró y corrigió un defecto real: un turno con `thinking=""` y tool calls podía producir tool results sin assistant/tool_calls precedente. `renderTurn()` ahora conserva el bundle incluso en tool-call-only turns y existe regresión explícita.

### F4 — categorías de knowledge estaban cerradas sólo en aplicación

`knowledge_store.category` ya era `TEXT NOT NULL` sin CHECK enum. El cierre arbitrario estaba en `KnowledgeCategory`/deserialización y en el filtrado del retriever. P-020 abre category a string en aplicación, mantiene categorías conocidas como hints compatibles y no añade migration.

### F5 — category inference debía ser hint, no frontera

El `EnhancedRetriever` previo podía invisibilizar una categoría nueva aunque key/content coincidieran. Ahora busca open-world y category sólo participa como factor de ranking.

### F6 — retrieval feedback global era contaminación cross-agent

El módulo mantenía rolling precision, feedback y una única `feedbackDb` como globals. Dos retrievers/DBs podían contaminarse. El feedback ahora pertenece a cada instancia de `EnhancedRetriever`; los facts/recovery críticos siguen en SQLite.

### F7 — persistence existente cubre la authority sin segundo store

- v5: working/episodic/semantic/procedural/relationship memory;
- v10: `knowledge_store` con category abierta durable, source, confidence, temporalidad/expiry;
- v18: Evidence Fabric para correlation/causation/provenance cross-domain;
- relationship memory conserva relaciones;
- P-022 conserva futura authority de world model/beliefs.

No se creó schema paralelo ni segunda source of truth.

### F8 — `event_stream` no se promovió por mera disponibilidad

`ContextManager` puede consumir events, pero el actor contract de todo `event_stream` no está unificado materialmente; por ejemplo, enhanced ingestion puede usar `sessionId` como `agentAddress`. P-020 no inyecta history/evidence masivo ni convierte Evidence Fabric en prompt dump.

### F9 — producer real de `knowledge_store` está conectado

`MemoryIngestionPipeline` corre post-turn en el runtime. Además de actualizar los cinco tiers, `ingestKnowledgeEnhancements()` extrae señales desde resultados de herramientas, aplica source/confidence/recency, detecta contradicciones, persiste facts confirmados en `knowledge_store`, emite eventos y poda stale/expired knowledge. Por tanto activated knowledge no es un consumer huérfano.

El enhanced producer actual es deliberadamente suplementario y especialmente útil para market/financial signals. El conocimiento no-market ya tiene authorities durables en semantic/procedural/working/episodic/relationship memory; no se añadió un extractor genérico paralelo sin evidencia de necesidad.
