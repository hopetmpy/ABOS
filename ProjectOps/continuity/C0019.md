`OBSERVE → MODEL → PREDICT → ACT → MEASURE → COMPARE → ATTRIBUTE → LEARN → UPDATE`.

## Auditoría de authority, producers, consumers y temporalidad

### Prediction record existente — REUSE

`adaptive_paths` ya es el prediction record durable y previo a la ejecución estratégica:

- `PathCandidate` contiene `hypothesis`, `assumptions`, `requiredCapabilities`, `environment`, `executor`, `sequence`, `expectedOutcome`, `expectedCostCents` y evidence refs;
- el path se crea/selecciona antes de `dispatchAgentTask`/mensajería;
- el planner expone `PlannerPathIntent.expectedOutcome` y la hipótesis estructurada antes de descomponer/ejecutar tareas;
- `pathSignature()` preserva identidad conceptual de estrategia, hipótesis, assumptions, environment/executor, sequence y expected outcome;
- `adaptive_paths.created_at` y los eventos causales prueban orden prediction-before-outcome.

Conclusión: crear `adaptive_predictions` duplicaría authority y fue RECHAZADO.

### Outcome record existente — REUSE

`adaptive_attempts` ya es el outcome record durable:

- cada attempt referencia `path_id` y opcional `task_id`;
- outcome soporta `success`, `partial_success`, `failed`, `blocked`, `unavailable`, `unknown`, `inconclusive`;
- guarda failure class/reason, observations, evidence, condition fingerprint, novelty, learned facts y retry eligibility;
- `recordSuccess()` y `recordFailure()` se ejecutan sólo después de un resultado/exception de ejecución;
- el Orchestrator enlaza tasks planificadas al strategic path y late results de rutas superseded no pueden resucitar el plan actual.

Conclusión: crear otro outcome ledger fue RECHAZADO.

### Evidence Fabric — REUSE REFERENCIAL

P-013 declara explícitamente que Evidence Fabric posee correlation/causation cross-domain y nunca canonical adaptive state. Es la authority correcta para registrar el evento `prediction compared / attributed`, referenciando path + attempt, no para duplicar prediction/outcome values como nueva source of truth.

### Skill Evolution — CONSUMER CONDICIONAL, NO OWNER UNIVERSAL

Skill Evolution ya tiene `skill_evaluations`, outcomes `success/failure/partial/inconclusive`, evidence refs, task/environment IDs, promotion/degradation lifecycle e independencia de evidence. Sin un `skillVersionId` causal explícito en un attempt concreto no se permite inferir que el error pertenece a una skill. P-023 no fabricará esa relación.

### Learning existente

- success terminal valida assumptions y marca path succeeded;
- `assumption_invalid` invalida el assumption correspondiente o degrada a UNKNOWN cuando no se puede discriminar cuál;
- terminal path failure invalida el strategic world belief con failure evidence;
- failed/equivalent path + unchanged conditions no puede repetirse como si no existiera evidencia nueva;
- capability/environment/resource/authorization failures generan rutas de acquisition/change/wait sin declararlas imposibles.

Esto ya implementa gran parte de `LEARN → UPDATE`; falta hacer explícita y causal la comparación/atribución sin duplicar state.

## Defecto material encontrado

`FailureClass` incluye `unknown`, pero `classifyFailure()` no posee ninguna salida `unknown`: cualquier error no reconocido cae al default `strategic_failure`, que es terminal.

Efectos observables actuales:

1. evidencia no clasificable se convierte en error estratégico/modelo;
2. `recordFailure()` persiste outcome `failed`;
3. el path termina `failed`;
4. el strategic belief puede invalidarse aunque la evidencia no demuestre contradicción.

Eso viola P-023 y el invariante transversal `UNKNOWN is first-class`.

## Decisión canónica

`DECISION_READY`:

1. REUSE `adaptive_paths` como prediction record previo.
2. REUSE `adaptive_attempts` como outcome record posterior.
3. EXTEND con una función de comparison/attribution pura y un Evidence Fabric event causal, sin nueva state authority.
4. CORRECT failure classification para que evidencia no reconocida resulte `unknown`, no `strategic_failure`.
5. Mantener patrones explícitos de strategic/model failure para evidencia que sí demuestra que la estrategia produjo un resultado inválido.
6. Mapear UNKNOWN a outcome `inconclusive`/path `unknown`, sin invalidar strategic belief.
7. Registrar comparison:
   - path final success → `confirmed`;
   - terminal strategic/assumption/prohibited/impossible contradiction → `contradicted`;
   - transient/capability/environment/resource/authorization/unknown → `inconclusive` con attribution específica, sin castigar el modelo.
8. Learning targets son referenciales y corresponden a authority real: assumption/world-belief/path/capability/environment/authorization/execution evidence. No se actualiza Skill Evolution sin skill-version causal explícita.
9. No calcular Brier/calibration mientras las predictions actuales tengan confidence no calibrada/null o muestra semánticamente insuficiente. `NO METRIC` es el resultado correcto, no un número inventado.

## Invariantes

1. Prediction precede outcome; no retrospective leakage.
2. Un execution failure no equivale a model error.
3. Measurement/UNKNOWN no se convierte en outcome negativo inventado.
4. Learning actualiza sólo la authority causalmente responsable.
5. No duplicar canonical beliefs, skills, evidence, paths, tasks ni outcomes.
6. Restart preserva path + attempt + causal Evidence events.
7. Reprocessing no puede aplicar learning terminal dos veces; existing belief invalidation y path status transitions deben seguir idempotentes.
8. Calibration sólo con probability semantics y muestra suficiente.
9. P-024 simulation y P-025 strategic review no se adelantan.

## Plan inmediato autorizado

1. Añadir comparison/attribution como módulo puro reutilizable sobre `PersistedPath` + `PathAttempt`/diagnosis.
2. Emitir Evidence Fabric event causal de comparación desde Adaptive Intelligence en success/failure/path completion.
3. Corregir `classifyFailure()` default a UNKNOWN y añadir matching explícito para strategic-invalid-result para no perder casos demostrados.
4. Corregir `recordFailure()` para UNKNOWN → `outcome=inconclusive`, `path=unknown`, `terminalForPath=false`.
5. Añadir tests negativos/adversariales que demuestren:
   - error irreconocible no invalida belief ni se convierte en failed/model error;
   - strategic invalid result sigue siendo contradicción terminal;
   - transient/external/capability produce comparación inconclusive con attribution correcta;
   - final success produce comparison confirmed;
   - multi-task intermediate success no confirma prematuramente el strategic expected outcome;
   - Evidence event enlaza prediction path y outcome attempt sin copiar una segunda canonical prediction/outcome store.
6. Ejecutar exact-head CI completo, revisar adversarialmente, integrar sólo después de branch+PR gates y exact-main.
