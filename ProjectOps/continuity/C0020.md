## Arquitectura decidida

1. E-xxx posee authority persistente propia bajo intelligence/state.
2. Registro canónico: question/hypothesis, variables + provenance, simulator/version, mode, seed/config, max-runs/cost budget, information gain, runs, summary, surprises, result, lesson y decision impact.
3. Runs persistidos por índice permiten restart/resume/idempotencia.
4. Counterfactuals son experimentos derivados enlazados al base y preservan variables no alteradas.
5. Simulation Evidence se registra como `inference`; nunca se promueve automáticamente a `observation`.
6. Calibration simulado→real exige Evidence externa `observation` y conserva el evidence ID.
7. Budget se valida antes de invocar cada run.
8. Simulator registry requiere exacto `id + version`; no existe fallback silencioso.
9. Workspace no entrega ToolContext/Environment executors ni acepta Promise como run válido. Esto evita un bypass provisto por el workspace, pero un callback JS registrado sigue siendo código del proceso: no se reclama sandbox universal.
10. P-025 decidirá cuándo/por qué invocar la capacidad dentro de Strategic Cognition.
