## Arquitectura integrada

1. E-xxx posee authority persistente propia bajo intelligence/state.
2. Metadata canónica incluye question/hypothesis, variables + provenance, simulator/version, mode, seed/config, budget, information gain, lifecycle, runs, summary/surprises/result, lesson y decision impact.
3. Runs persistidos por índice permiten restart/resume/idempotencia.
4. Counterfactuals enlazan experimento derivado al base y preservan variables no alteradas.
5. Simulation Evidence permanece `inference`; no se promueve automáticamente a `observation`.
6. Calibration exige Evidence externa `observation` y rechaza evidencia originada en simulation authority.
7. Budget se comprueba antes de cada run.
8. Simulator registry requiere exacto `id + version`; no existe fallback silencioso.
9. Workspace no entrega ToolContext/Environment executors ni acepta Promise como run válido.
10. `listExperiments()` permite discovery bounded tras restart sin requerir conocer de antemano el E-xxx exacto.
