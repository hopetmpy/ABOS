## Hipótesis auditadas

### H0 — `NO_CHANGE`

**FALSADA.**

Evidencia discriminante:
- `src/orchestration/plan-mode.ts::reviewPlan()` aprueba siempre `auto`, incluso sobre su threshold, y `consensus` también devuelve aprobación con feedback de stub;
- `supervised` no evalúa estrategia: sustituye review por `awaiting human approval`;
- `src/__tests__/orchestration/plan-mode.test.ts` codifica esas tres conductas como resultados esperados;
- `Orchestrator.handlePlanReviewPhase()` hardcodea `mode: "auto"` y, si falta o no parsea el plan persistido, avanza a `executing` sin review material.

El runtime actual no satisface la semántica de P-025.

### H1 — `EXTEND_ADAPTIVE_PATH`

**PARCIALMENTE RECHAZADA COMO OWNERSHIP PRIMARIO / REUSE CONFIRMADO.**

`AdaptivePathEngine` ya posee route identity, novelty, attempt history, assumptions, facts/beliefs, evidence, failure learning y prediction resolution. Esa authority debe ser reutilizada por strategic review; convertirla en un segundo reviewer mezclaría responsabilidades. Sólo se permiten extensiones de exposición/wiring si son necesarias para que el reviewer consuma evidence existente.

### H2 — `CORRECT_PLAN_MODE_REVIEW`

**CONFIRMADA.**

El defecto principal de approval vive en orchestration/review heredado. La corrección pertenece al flujo existente; no requiere una segunda authority de plan/review.

### H3 — `UNIFY_STRATEGIC_DECISION_FLOW`

**CONFIRMADA.**

Hoy el planner ya consume Adaptive Path context, environment snapshots y capability state, pero el review no consume esa evidence y P-024 simulation tampoco llega al planner/reviewer. Además, el plan/path/tasks se materializan antes de que el review haya demostrado readiness. Debe existir una sola transición causal:

`planner candidate -> substantive strategic review -> select/bind/materialize -> execution boundary`.

La review no debe ser bypass silencioso, y un reject/revise no debe dejar trabajo ejecutable como si hubiese sido aceptado.

### H4 — `CREATE_NEW_STRATEGIC_AUTHORITY`

**FALSADA.**

Las responsabilidades materiales ya existen distribuidas y con authorities canónicas:
- planner/orchestration: generación y descomposición;
- Adaptive Path: route/evidence/assumption/learning authority;
- CapabilityResolver/Registry: execution-readiness y capability gaps;
- EnvironmentRegistry/providers: environment observation/execution authority;
- SimulationWorkspace: experiment/counterfactual/probe evidence consumible;
- PolicyEngine + policy authorization: explicit effect/creator boundary.

Crear otra strategic authority duplicaría ownership.

## Mapa causal / ownership decidido

### REUSE

- `AdaptivePathEngine` / `AdaptiveStore` para paths, attempts, beliefs, assumptions y evidence.
- `CapabilityResolver` / capability registry para `VERIFIED_AVAILABLE`, probe, acquire, compose, construct, unauthorized/prohibited y UNKNOWN.
- environment registry/snapshots para condiciones y disponibilidad observada.
- `SimulationWorkspace` como evidence/decision-impact consumible, no planner paralelo.
- policy/creator authorization para `REAL_BOUNDARY` explícito.
- Task graph, worker harness, transport receipts y recovery existentes.

### CORRECT

- `reviewPlan` y su wiring de production: no constant approval, no nominal consensus, no human fallback universal.
- fail-open de `plan_review` ante plan ausente/malformado.
- ordering que materializa path/tasks antes de review suficiente.

### UNIFY

- planner + Adaptive Path + capabilities + environments + simulation/evidence deben alimentar el mismo review causal antes de ejecución.

### EXTEND

- el contrato de planner/review sólo donde falte representar alternativas, falsificadores/premortem, evidence/discriminants y review outcome recuperable.
- planner context con resultados/interpretaciones P-024 relevantes al Goal/Path, preservando provenance.

### NO_CHANGE

- policy effect boundaries y creator signature authorization;
- transport/idempotence/recovery de child execution;
- conceptual path novelty como identidad/equivalencia, no como score de calidad estratégica.

### CREATE

- **NO JUSTIFICADO.** No se crea nueva authority material.

## Adversarial review previo a implementación

Se atacó la decisión contra:
- fake consensus/autoapproval;
- fixed threshold tratado como inteligencia;
- human approval circular;
- bypass por plan ausente/corrupto;
- capability lexical match promovido indebidamente a execution readiness;
- policy boundary rebajado a juicio interno;
- Adaptive Path convertido accidentalmente en reviewer paralelo;
- P-024 simulation convertido en planner paralelo;
- path/tasks persistidos antes de review y residuos de planes rechazados;
- retries/equivalent-path replay;
- late result/double execution/restart.

Resultado: las incertidumbres restantes son de implementación/compatibilidad y tests, no cambian el ownership ni la dirección técnica. `DECISION_READY` queda concedido.

## Decisión adoptada

Implementar P-025 como **`CORRECT + UNIFY + targeted EXTEND` sobre authorities existentes**.

Secuencia elegible:
1. corregir el contract de strategic review y sus tests para que approval requiera juicio/evidence real y para que UNKNOWN/revise/boundary sean explícitos;
2. hacer que production orchestration obtenga review context canónico y falle cerrado si el artifact necesario está ausente/corrupto;
3. mover selección/materialización de path/tasks después del review aprobado, o demostrar una semántica transactional equivalente que no deje trabajo ejecutable tras reject;
4. proyectar P-024 simulation/decision-impact relevante dentro del strategic context sin convertir simulation en planner;
5. conservar creator/policy approval sólo para `REAL_BOUNDARY`;
6. ejecutar tests focales, typecheck/build, full suite/CI y adversarial cases antes de integración.
