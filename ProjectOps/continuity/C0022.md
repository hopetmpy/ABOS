## Objetivo

Maximizar resultado útil por recurso cognitivo gastado, no simplemente minimizar tokens. Antes de inferencia, ABOS debe poder considerar memoria/cache, retrieval/context activation, cálculo/código/tool, skill/procedure, simulation/replay e inferencia; cuando requiera modelo debe elegir contexto/model/reasoning de forma compatible con autoridad, provider boundary, model lock y budgets existentes.

La optimización no puede degradar silenciosamente success/quality. El coste material debe incluir cuando aplique tokens, latencia, dinero, contexto, retry/rework y evidencia de outcome; reusable learning creado forma parte del valor, no sólo del gasto.

## Auditoría inicial — evidencia encontrada

### Inference / model fabric

`src/inference/budget.ts` ya implementa `InferenceBudgetTracker` sobre el ledger persistente canónico:
- per-call ceiling;
- hourly/session/daily budget arithmetic;
- record/get de coste por sesión/día/hora/modelo;
- hot strategy config sin recrear el loop.

`src/inference/router.ts` ya implementa:
- descubrimiento/selección de modelos con active model, routing matrix, tier y provider compatibility;
- open discovery de modelos habilitados;
- presupuestos antes del call;
- `inference.attempt_started` durable antes del external call;
- tokens/coste/latencia reales después del response;
- ledger de coste + Evidence `inference.succeeded`;
- timeout y provider-error con external settlement UNKNOWN;
- provider boundary y fallback configurado.

Conclusión provisional: otro model router o ledger de coste sería duplicación.

### Cognitive Fabric / skills / intelligence / state

El Required-Context demuestra authorities ya existentes que deben auditarse antes de crear:
- `src/memory/`: context manager, retrieval/enhanced retrieval, knowledge/episodic/procedural memory, compression, context budget y tools;
- `src/skills/`: registry/loader + evolution sobre experiencia verificable;
- `src/intelligence/`: Adaptive Path, Prediction Learning, World Model-related store y Simulation Workspace;
- `src/state/`: database/schema canónicos, más sidecars de simulation/world model.

La presencia de estas piezas no demuestra todavía que P-026 esté satisfecho. Falta mapear producers/consumers/callers, outcomes aprendibles, persistencia, tests y bypass paths.

## Gaps provisionales a falsar

La lectura inicial de `InferenceRouter` sugiere, pero todavía no cierra, estos posibles gaps:
- el router decide entre modelos, no entre `no-model` vs memory/tool/skill/simulation/model como decisión cognitiva común;
- registra coste/tokens/latencia de inference, pero no se ha demostrado todavía una authority que conecte retry/rework/success evidence/reusable learning por task class a una decisión adaptativa de compute;
- la routing matrix/tier/config son hints/boundaries útiles, pero no se ha demostrado todavía aprendizaje outcome/cost que explique escalamiento/deescalamiento;
- no se ha demostrado aún un receipt durable que justifique causalmente por qué una tarea llamó o no llamó a modelo.

Estos son findings de auditoría, no claims de ausencia definitivos.

## Hipótesis abiertas

### H0 — `NO_CHANGE`

El sistema actual ya satisface materialmente P-026 mediante composición de InferenceRouter/Budget + Cognitive Fabric + Skills + Prediction Learning/Simulation. Debe buscarse evidencia positiva antes de falsarla.

### H1 — `EXTEND_INFERENCE_ROUTER_ONLY`

La responsabilidad completa pertenece al inference fabric y basta extender model routing. Esta hipótesis sería falsada si la decisión P-026 necesita escoger rutas no-model cuya ownership no pertenece al router.

### H2 — `CREATE_COGNITIVE_COST_CONTROLLER_OVER_EXISTING_AUTHORITIES`

Hace falta una authority estrecha de **decisión cognitiva**, no otro executor/ledger/router: compara rutas ya existentes, registra rationale/expected cost-value y delega ejecución a memory/tools/skills/simulation/inference canónicos.

### H3 — `UNIFY_OUTCOME_COST_LEARNING_WITH_EXISTING_EVIDENCE`

La adaptación debe reutilizar P-023/P-024/Evidence/skill learning para aprender outcome/cost por task class y evitar una segunda learning authority. Puede coexistir con H2 si el controller sólo consume/proyecta evidencia canónica.

### H4 — `CREATE_PARALLEL_COST_OR_MEMORY_OR_MODEL_AUTHORITY`

Rechazada por default salvo evidencia falsadora fuerte: ya existen ledger, router, memory, skill, simulation y state owners. Crear duplicados violaría one-authority-per-concern.

## Invariantes

- preservar manual model lock;
- preservar budget ceilings y Treasury ownership donde corresponda;
- preservar provider/connection boundary y UNKNOWN;
- no degradar quality/success silenciosamente para ahorrar tokens o dinero;
- no convertir una static threshold/routing matrix en claim de inteligencia adaptativa;
- no crear segundo ledger de inferencia, model registry/router, memory store, skill registry, simulation workspace ni database authority;
- una ruta no-model debe demostrar success evidence comparable cuando se use para justificar ahorro;
- fallar barato no es ahorrar si aumenta retry/rework o reduce outcome;
- source-level savings no equivalen a material savings sin evidencia proporcional.
