## Objetivo

Extender la authority existente de actor selection para que ABOS pueda seleccionar ejecución local, agent/worker/child u otro actor elegible según task requirements, verified capabilities, experiencia/outcome evidence contextual, availability/health, environment access, coste/latency, trust/authority y constraints, sin duplicar Capability, Environment, Evidence, Policy, lifecycle ni Task authority.

## Invariantes

- no convertir roles/departments en taxonomy cerrada ni authority de competencia;
- parent y child conservan authority propia; no se prestan permisos por selección;
- UNKNOWN no equivale a false, cero coste ni incapacidad;
- historical performance se interpreta por task class/contexto, no como reputación global rígida;
- coste esperado considera evidence disponible de Task/environment; ausencia permanece UNKNOWN y no se fuerza a cero;
- availability/health/environment stale no se trata como readiness actual;
- registration order o “primer idle” no puede ser criterio material de selección;
- delegation puede seleccionar ejecución local si la evidencia la justifica;
- failure/reassignment actualiza evidence; no etiqueta incapacidad permanente;
- no crear segunda Capability, Environment, World Model, Evidence, Cognitive Cost, Policy/Authority, child lifecycle o task authority.

## Implementación material

- `Orchestrator.matchTaskToAgent()` usa un matcher evidence-driven sobre idle workers/children y parent/local candidate; `getBestForTask()` y busy-agent reassign dejan de ser criterios del path canónico P-028.
- Required capabilities, preferred environment, current health/availability, actor-specific environment resources, contextual Task outcomes, cost/latency observados, role hint y authority se proyectan en un receipt explicable.
- Parent/local competence usa Capability Fabric verificada; child/worker competence no hereda capabilities del parent.
- `EnvironmentResource.capabilities` no se promociona circularmente a competence cuando puede haber nacido de los requirements solicitados por la propia Task.
- UNKNOWN capability/cost/history permanece UNKNOWN; absence no se convierte en incapacidad ni coste cero.
- Task history se contextualiza por exact capability-set o role fallback; no se persiste reputación global rígida.
- Cada decisión selected/unresolved se registra en Evidence Fabric sin apropiarse de Task authority.
- Failure attribution usa causal selection receipts e idempotencia por causation id; stale actor outcomes y restart replay no contaminan history.
- Spawn continúa por la ruta canónica `config.spawnAgent`/Environment Mobility; P-028 sólo reevalúa el actor después de discovery.
- Existing eligible actor se conserva si spawn/mobility discovery falla; no se transforma dificultad de discovery en pérdida del actor ya justificable.

## Adversarial review — fallos encontrados y corregidos

- capability labels de `EnvironmentResource` podían convertirse circularmente en “competence” aunque provinieran de los requirements solicitados; se rechazó esa promoción y se exige outcome actor-specific para worker/child.
- failure history podía perder attribution porque `failTask()` limpia `assigned_to`; se añadió causal attempt evidence antes de esa pérdida de identity.
- un resultado stale de un actor anterior podía intentar heredar el Task actual; sólo el último `delegation_selected` del mismo actor es causal.
- replay/restart podía contar el mismo failure dos veces; `causation_id=selectionEventId` vuelve el outcome idempotente.
- spawn discovery se había debilitado cuando parent/local UNKNOWN ya era seleccionable; se preservó discovery cuando existe role/capability need unresolved y se mantiene Environment Mobility como owner.
- fallo adicional encontrado en esta reauditoría: el path asíncrono reconstruye `TaskNode` desde `task_graph` y no lleva `adaptive_task_bindings`; un failure de una Task `caps:*` podía reetiquetarse como `role:*`. Se corrigió haciendo que el outcome derive `taskClass` y `requiredCapabilities` del receipt causal de selección. Regresión dedicada: `competence-delegation-causal-context.test.ts`.

## Adversarial targets cubiertos

- order-independence con actores heterogéneos;
- verified competence supera role-only bajo requirements materiales;
- requested resource labels no se auto-promueven a competence;
- parent Capability Fabric no se presta al child;
- unavailable/dead actor no gana y preferred environment es constraint material;
- menor coste conocido discrimina entre actores con evidence de outcome equivalente;
- failed attempt persiste aunque `assigned_to` sea limpiado y la siguiente decisión puede elegir otro actor;
- stale actor outcome se rechaza y restart replay no duplica sample;
- receipt se reconstruye desde Evidence Fabric tras restart;
- missing capability/cost permanece UNKNOWN;
- path canónico no consulta `getBestForTask()`;
- parent competence verified evita spawn innecesario;
- parent competence unresolved conserva delegated spawn discovery;
- failure asíncrono reconstruido conserva exact causal `caps:*` context aun cuando el `TaskNode` de result-path no lleve binding.
