## Objetivo

Migrar las autoridades operativas vivas desde documentos raíz monolíticos hacia una matriz ProjectOps modular, preservando historia y protocolo, manteniendo un único router raíz y adaptando la política de host a la visibilidad pública de ABOS.

## Restricción cumplida

La arquitectura de ProjectOps/ZeroIQ/CATO se utilizó como referencia de **mecanismo**. No se importaron semántica predictiva, Android mission semantics, estados, thresholds, métricas, gates o resultados de otro proyecto.

## Resultado implementado

- root `AGENTS.md`: router ABOS/ProjectOps;
- protocolo completo legacy: `ProjectOps/system/ABOS_OPERATING_PROTOCOL.md`;
- continuidad legacy: `ProjectOps/continuity/C0000-legacy.md`;
- plan legacy: `ProjectOps/plan/LEGACY_FULL_PLAN.md`;
- manifests vivos: PROJECT / CONTINUITY / PLAN;
- active segment: C0001;
- módulos P-001..P-005;
- adaptive reasoning layer ABOS-specific;
- acceptance suite A–N con `BEHAVIORAL_SUITE_NOT_YET_EXECUTED`;
- host boundary `PUBLIC_TRACKED_DOCUMENTARY_MATRIX`;
- verifier estructural standalone;
- root CONTINUITY/PLAN retirados para no competir con manifests ProjectOps.

## Publicación y secretos

ABOS es público. Esta migración no convierte ProjectOps en memoria privada. El host mode prohíbe secrets, wallet keys, OAuth tokens, API keys, credenciales cloud, datos privados y razonamiento privado.

Estado runtime `~/.abos` permanece fuera de ProjectOps.
