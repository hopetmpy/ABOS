# P-004 — Reconciliar documentación arquitectónica con source/runtime v0.3.0 actual

State: PLANIFICADO
Priority: MEDIA

Required-Context:
- `AGENTS.md`
- `ProjectOps/PROJECT.md`
- `ARCHITECTURE.md`
- `DOCUMENTATION.md`
- `README.md`
- `package.json`
- `src/state/schema.ts`
- `.github/workflows/ci.yml`

## Objetivo

Reauditar y actualizar documentación técnica que haya quedado detrás del source actual, manteniendo topología útil y eliminando claims de versión/contadores obsoletos.

## Evidencia que origina el P

- `src/state/schema.ts`: `SCHEMA_VERSION = 14`.
- `ARCHITECTURE.md`: conserva texto que describe migrations `v1 -> v8`.
- PRs posteriores al documento añadieron/consolidaron AI Connections/Codex, Adaptive Path, environments/lifecycle/mobility, execution continuity y fixes de autoridades.

Este hallazgo demuestra drift puntual; no demuestra que toda la documentación esté obsoleta.

## Auditoría previa obligatoria

1. comparar cada sección material con source actual;
2. buscar contadores frágiles (tools/tasks/tests/schema/etc.);
3. distinguir diagramas conceptuales válidos de cifras versionadas;
4. revisar PRs/commits que cambiaron contratos;
5. no modificar source para satisfacer un doc antiguo salvo que source sea realmente defectuoso.

## Dirección prevista

Preferir documentación por contratos/autoridades sobre contadores que envejecen rápido. Cuando un número sea útil, vincularlo a versión/source y evitar presentarlo como eterno.

## Criterios de aceptación

- no contradicción conocida entre docs y authorities actuales;
- schema/runtime/version claims reconciliados;
- AI connections/adaptive/environment/child boundaries representados correctamente donde corresponda;
- no duplicación de ProjectOps dentro de docs técnicas;
- cambios documentales validados por diff y referencias source.

## Definición de HECHO

HECHO cuando la auditoría completa de documentación técnica relevante no deje contradicciones conocidas materiales con el source actual y la evidencia de revisión quede registrada.
