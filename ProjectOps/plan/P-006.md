## Objetivo

Restaurar `pnpm audit` green mediante una remediación compatible y auditada de advisories vigentes, sin ocultarlos ni ignorarlos globalmente, y dejar ABOS sobre runtimes Node mantenidos y realmente soportados por su dependency graph.

## Hallazgo de origen

El security-audit detectó:
1. `stream-json <=3.4.0` — `GHSA-528h-pc64-c93x`;
2. `vitest >=2.1.0 <4.1.11` — `GHSA-82fw-gwwq-j7x9`;
3. `@vitest/mocker >=2.1.0 <4.1.11` — mismo advisory transitivo.

Eran deuda preexistente, no regresión creada por ProjectOps.

## Auditoría y decisiones

### Vitest

- Se elevó a `^4.1.11`.
- Vitest 4 retiró `--grep`; `test:security` y `test:financial` migraron a `--testNamePattern`.
- Security, financial y full suite pasan con la nueva línea.

### stream-json / Solana

- Se añadió override selectivo `stream-json@<=3.4.0 -> 3.6.0`.
- No fue necesario elevar `@solana/web3.js`.
- Smoke JSON-RPC de Solana y suites integradas pasaron.

### Runtime Node

Node 20 quedó retirado porque la línea segura de `stream-json`/`stream-chain` exige Node >=22 y Node 20 está EOL. Conservarlo habría requerido engine bypass, aceptar el advisory o mantener una fork propia.

Contrato final:
- Node 22 y Node 24 soportados;
- Node 22 default/recommended;
- `engine-strict=true` preservado.

### better-sqlite3

Se falsaron alternativas antes de elegir el graph final:
- `13.0.3`: descartado porque fresh install Windows Node 24 cayó a `node-gyp` y falló por toolchain;
- `12.12.0`: descartado porque no estaba publicado en npm;
- `12.11.1`: adoptado; fresh install/build/state smoke/Windows regressions PASS en Node 22 y 24.
