## Objetivo

Restaurar `pnpm audit` green mediante una remediación compatible y auditada de advisories actuales, sin ocultarlos, ignorarlos globalmente ni introducir una actualización mayor ciega.

## Hallazgo que origina el P

Durante la validación del cutover ProjectOps, el job `security-audit` falló con tres findings moderados:

1. `stream-json <=3.4.0` — advisory `GHSA-528h-pc64-c93x`, path observado `.>@solana/web3.js>jayson>stream-json`, patched `>=3.5.0`.
2. `vitest >=2.1.0 <4.1.11` — advisory `GHSA-82fw-gwwq-j7x9`, direct dev dependency.
3. `@vitest/mocker >=2.1.0 <4.1.11` — mismo advisory transitivo vía Vitest.

La rama ProjectOps no modificó `package.json` ni `pnpm-lock.yaml`; por tanto el fallo se clasifica **PREEXISTING/EXTERNAL_ADVISORY_DISCOVERED_DURING_VALIDATION**, no regresión causada por P-001/P-002.

## Riesgo de una corrección ciega

- Vitest patched requiere `>=4.1.11`, salto mayor desde v3.2.7; puede cambiar config/API/behavior de tests.
- `stream-json` es transitivo bajo `@solana/web3.js > jayson`; un override debe probar compatibilidad real, no asumir semver interna.
- elevar dependencias puede afectar Node 20/22, wallet/Solana paths, mocking, test discovery o CI timing.

## Auditoría previa obligatoria

1. confirmar advisories vigentes y versiones actuales disponibles;
2. identificar por qué cada dependencia existe y qué source la consume;
3. evaluar upgrade directo, transitive parent upgrade, `pnpm.overrides` o reemplazo;
4. revisar release notes/breaking changes de Vitest 4;
5. verificar compatibilidad Node 20/22;
6. evitar una excepción de audit salvo decisión temporal explícita y justificada;
7. actualizar lockfile de forma determinista;
8. ejecutar typecheck/build/full tests/security tests/Windows y `pnpm audit`.

## Semántica a preservar

- no degradar CI para volverlo verde;
- no bajar severidad por configuración arbitraria;
- no eliminar tests vulnerables sin reemplazar cobertura;
- no afectar wallet/identity solo para resolver una dependencia transitiva;
- no declarar fixed hasta que el audit del lockfile actual pase.

## Criterios de aceptación

- `pnpm audit`: PASS sin advisories no aceptados;
- Node 20: typecheck/build/tests PASS;
- Node 22: typecheck/build/tests PASS;
- security-focused tests PASS;
- Windows regression PASS;
- public distribution smoke PASS;
- diff de dependency graph auditado;
- ProjectOps reconciliado con evidencia.

## Definición de HECHO

HECHO solo cuando el security-audit autoritativo pase sobre el SHA integrado y no exista regresión observada en gates de compatibilidad.
