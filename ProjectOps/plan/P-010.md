## Objetivo

Convertir policy de una clasificación parcial a una autoridad runtime consistente: permitir, denegar, requerir autorización/confirmación, poner en quarantine, reanudar o expirar decisiones sin perder provenance ni ejecutar el efecto antes del gate.

## Problemas a auditar

- default allow y risk levels pueden no imponer el gate que el nombre sugiere;
- validaciones chain-specific pueden asumir EVM donde existe Solana;
- quarantine/approval pueden carecer de continuation semantics reales;
- una autorización humana no debe convertirse en permiso global indefinido.

## Arquitectura objetivo

Decision record durable con scope de actor/acción/recurso/coste/tiempo, provenance, constitution result, policy result, required authority, expiry/idempotency y continuation token seguro cuando proceda.

## Invariantes

- constitution prevalece sobre survival/economics;
- denial no se camufla como technical failure;
- no bypass equivalente de una prohibición;
- authorization scope mínimo y explícito;
- chain/provider validation debe usar autoridad adecuada, no regex accidental.

## Failure matrix

Approval llega tarde, restart mientras espera, recurso cambia, balance/coste cambia, duplicate approval, cancellation, revoked authorization, provider unavailable, child unreachable.

## Definition of Done

Un flujo bloqueado puede persistir y reanudarse exactamente una vez con autorización válida; un deny/prohibited nunca ejecuta side effects; EVM/Solana y actors distintos usan validación/autoridad correctas.
