## Objetivo

Dar a ABOS evidencia durable y correlacionable para responder qué decidió, por qué autoridad, qué intentó, qué ejecutor usó, qué costó, qué observó, qué falló, qué aprendió y qué cambió después, sin crear un segundo ledger de dominio.

## Arquitectura objetivo

Correlation/causation IDs y eventos abiertos para decision/path/capability/tool/environment/inference/economic/learning/lifecycle, con provenance y timestamps. Los eventos referencian autoridades canónicas; no duplican saldo, task state o world state como nuevas fuentes primarias.

## Auditoría previa — hechos

1. `StructuredLogger` y `MetricsCollector` son observabilidad operacional; stdout/sinks y métricas in-process no constituyen audit trail durable.
2. `metric_snapshots` sí tiene producer heartbeat, pero es una vista agregada/derivada y no una autoridad causal.
3. `event_stream` existe desde v9 y tiene un consumidor real en planner-context, pero `src/memory/event-stream.ts` lo define expresamente como memoria del agente y permite `compact()` y `prune()`. Por semántica no puede alojar evidencia crítica que P-013 prohíbe muestrear/perder.
4. `event_stream` además conserva `token_count`/`compacted_to` y un `EventType` orientado a memoria/orchestration; reutilizarlo como audit fabric mezclaría responsabilidades aunque el nombre parezca genérico.
5. Authorities de dominio ya existen y deben conservarse: `policy_decisions`, `self_mod_transactions`, `adaptive_attempts`/`adaptive_evidence`, `environment_resource_events`/migrations, `heartbeat_history`, `inference_costs`, `turns`/`tool_calls`, TaskGraph y ledgers económicos.
6. `ToolCallResult.id` se reemplaza por el tool-call ID nativo de la inferencia y luego se persiste en `tool_calls` con FK lógica al turn; esa identidad debe reutilizarse.
7. `PolicyEngine.persistDecision()` acepta `turnId`, pero el protected execution path hoy no lo pasa. `PolicyRequest.turnContext` tampoco transporta `turnId/toolCallId/correlationId`. Se pierde una relación durable antes del efecto.
8. Policy ya persiste lifecycle `running/succeeded/failed`; la nueva evidence fabric debe referenciar ese decision ID, no volver a decidir policy.
9. P-012 `self_mod_transactions` posee transaction ID y lifecycle durable, pero deliberadamente está debajo de Policy y hoy no conoce turn/tool/policy/correlation. Esa es la dependencia concreta que P-013 debe cerrar sin trasladar Policy dentro de self-mod.
10. Heartbeat ya resuelve timeout/late-success sobre la misma fila `heartbeat_history`; P-013 debe referenciar ese history ID y conservar esa semántica, no crear un scheduler paralelo.
11. Inference cost ledger ya conserva `sessionId`, `turnId`, model/provider/tokens/cost/latency para completions registradas; los intentos de modelo fallidos/fallback previos al success no tienen hoy evidencia durable equivalente.
12. Environment resource/migration stores ya poseen eventos de lifecycle con IDs y goal/path/task references. Son authorities de dominio; el fabric sólo las enlaza.
13. Adaptive Intelligence ya clasifica outcomes/failure/evidence/assumptions/world facts. P-013 no debe duplicar epistemic state; sólo referenciar sus IDs y registrar causalidad transversal.
14. Sanitización de prompt/tool output no es redacción de audit: P-013 necesita una redacción estructural propia y conservadora, y debe preferir hashes/IDs/resúmenes sobre copiar args/results crudos.

## Hipótesis competidoras y decisión

### A. Convertir `event_stream` de memoria en audit fabric

**DESCARTADA.** Su authority actual es memoria; puede compactarse y podarse. Hacer críticos authority/money/self-mod dependientes de una tabla deletable viola el invariante de P-013 y acoplaría memoria/context budgeting con auditoría.

### B. Añadir `correlation_id` a cada ledger y no crear timeline transversal

**INSUFICIENTE COMO SOLUCIÓN COMPLETA.** Los domain rows conservarían asociación, pero reconstruir un flujo abierto obligaría a conocer todas las tablas presentes/futuras y no produciría una secuencia causal uniforme.

### C. Crear sólo un log genérico escrito después de cada efecto

**DESCARTADA PARA EVENTOS CRÍTICOS.** Un crash entre el domain commit y el append dejaría estado real sin vínculo causal; un append previo sin domain binding dejaría intents ambiguos.

### D. Hybrid evidence fabric — SELECCIONADA

Crear una única authority transversal cuyo **único estado primario es causalidad/correlación**, no el estado de negocio:

1. schema v18 añade `evidence_events`, append-oriented, con ID propio, `correlation_id`, `causation_id`, event/domain abiertos, referencia `authority_type/authority_id`, referencias opcionales goal/task/turn/tool-call, epistemic status, payload/provenance redactados y timestamp/orden durable;
2. `authority_type/authority_id` apuntan al ledger real; el event no copia balance/task state/policy state/self-mod state como nueva fuente de verdad;
3. para authorities críticas donde un crash podría romper trazabilidad, correlation metadata entra en el mismo domain row y el evento crítico se escribe dentro de la misma transacción SQLite cuando sea materialmente posible;
4. primera integración crítica: turn/tool → policy decision/execution → self-mod transaction/lifecycle. Esto cierra la dependencia P-012;
5. después se conectan inference attempts/cost, adaptive path/evidence, environment lifecycle/mobility y heartbeat history usando sus IDs existentes;
6. `event_stream` de memoria permanece separado y puede seguir compactándose/podándose sin afectar audit evidence;
7. logger/metrics/alerts pueden proyectar correlation IDs para operación, pero nunca sustituyen la evidencia SQLite durable.

## Semántica de identidad causal

- `correlation_id` identifica el flujo raíz durable, no idempotencia ni ownership de efectos.
- Cuando existe Goal authority, el goal es el root natural; para un turn interactivo no asociado a goal, el turn es root natural; heartbeat/background usa su ejecución durable cuando no hay una raíz superior. La representación concreta debe preservar namespace/authority en vez de fabricar una segunda entidad sólo para obtener un ID.
- `causation_id` enlaza con el evento causal precedente cuando es conocido; no se usa como sustituto de task dependency, policy scope hash, claim token, lease, idempotency key o transaction ownership.
- legacy rows sin correlación permanecen `legacy/unknown`; no se backfillea causalidad inventada.

## Redacción y minimización

- evidence events almacenan IDs, hashes, clasificación, unidades y resúmenes mínimos; no copian argumentos/resultados completos por defecto;
- redactar estructuralmente credentials/autorizaciones/secrets conocidos (`authorization`, cookies, API/private/secret keys, password/passphrase, access/refresh tokens, mnemonic/seed phrases y equivalentes normalizados);
- scrub de formatos evidentes puede complementar, nunca justificar el claim de detectar todo secreto posible;
- signatures/challenge evidence siguen bajo su domain authority cuando ya existen; el fabric referencia el decision ID en lugar de replicarlas;
- contenido externo o privado no entra en payload salvo necesidad demostrada y transformación explícita.

## Failure matrix / premortem

1. crash después de policy/domain commit pero antes de generic event → correlation crítica debe persistirse atómicamente con la authority o la operación no puede declarar trace completa;
2. crash después de intent y antes de effect → intent queda distinguible de success; no se sintetiza outcome;
3. timeout con late success → conservar ID original y reconciliar el mismo authority; no emitir un segundo intento ficticio;
4. retry equivalente → correlation no reemplaza idempotency/dedup/lease; esos mecanismos siguen en su domain;
5. restart → reconstrucción usa SQLite IDs, no AsyncLocal/process memory como autoridad;
6. malformed/unserializable payload → no debe impedir un efecto crítico si el domain authority puede persistir su correlation mínima; event writer debe fallar de forma explícita según la fase y no filtrar secrets en errores;
7. redaction miss → minimizar payload reduce blast radius; tests adversariales cubren key-based secrets y bearer-like strings, sin afirmar exhaustividad imposible;
8. sampling/compaction → prohibited para `evidence_events`; memoria/metrics pueden muestrear independientemente;
9. timestamp collision/clock skew → usar orden de inserción/ID además de timestamps; timestamp solo no define causalidad;
10. generic event duplicado por retry → domain authority/id + correlation permiten reconocer equivalencia; fabric no decide si el side effect puede repetirse;
11. correlation propagation perdida → evento/domain row conserva UNKNOWN explícito o la operación crítica fail-closed si el contrato exige traceability pre-effect;
12. segundo ledger accidental → tests/contract impiden payloads que pretendan reemplazar state; queries de estado siguen leyendo domain authorities.
