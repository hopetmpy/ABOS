## Objetivo

Convertir las piezas cognitivas existentes en una sola autoridad lógica que permita amplio conocimiento persistente con un working set pequeño y relevante. No crear “otra memoria”.

## Estado observado

La auditoría estructural encontró múltiples piezas: retrievers, context manager, compression, aggregation, knowledge/events; algunas avanzadas no están alcanzadas desde el runtime principal. Antes de decidir quién manda, seguir producers/consumers/tests/persistence y clasificar: authority, extension, legacy, duplicate, orphaned o experimental.

## Arquitectura objetivo

Persistent Cognitive Universe + Context Activation Engine + Working Cognitive Set. Progressive disclosure conceptual:
- L0 Core: constitution/identity/goal/authority/current state;
- L1 Index: cheap summaries/keys;
- L2 Relevant: richer summaries;
- L3 Deep: episodes/procedures/relations/evidence;
- L4 Raw: logs/files/conversations sólo cuando aportan valor.

Los niveles son activación/representación de una misma autoridad, no cinco stores competidores.

## Open knowledge

Knowledge debe admitir categorías/relaciones nuevas con provenance, confidence, temporalidad y links; taxonomías existentes pueden mantenerse como etiquetas compatibles, no universo cerrado.

## Activation policy

Relevance + causality + uncertainty + dependencies + value-of-information + context cost. Lifecycle conceptual: DORMANT → ACTIVATED → EXPANDING → SATURATED → COMPRESSED/CHECKPOINTED → DORMANT; nombres finales se reconciliarán con source.

## Recovery

Checkpoint conserva objetivo, hipótesis, evidencia, decisiones, errores, lessons, open questions y reactivation conditions. Restart debe reconstruir working set sin recargar todo el histórico.

## Validation

Comparar baseline vs Cognitive Fabric en tasks multi-turn: recall correcto, menor contexto, no pérdida de evidence crítico, restart, branch activation/deactivation, conflicting memories y stale facts.

## Definition of Done

El runtime principal usa una autoridad cognitiva reconciliada; conocimiento amplio puede permanecer persistente/dormant y activarse bajo demanda sin prompt masivo, y no quedan componentes avanzados presentados como activos si siguen desconectados.
