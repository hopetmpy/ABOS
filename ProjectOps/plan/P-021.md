## Objetivo

Permitir que ABOS convierta experiencias repetibles en procedimientos reutilizables, versionados y verificables, reduciendo razonamiento/tokens sin cristalizar errores como conocimiento procedural.

## Modelo objetivo

Experience/evidence → pattern candidate → candidate skill → applicability/inputs/preconditions → sandbox/replay validation → ACTIVE → usage observations → evolve/deprecate/fallback. Skills son procedimientos; memory conserva hechos/episodios y Capability Fabric conserva lo que puede ejecutarse.

## Invariantes

- una ejecución exitosa aislada no basta para promover una skill crítica;
- skill no puede elevar permisos ni ocultar tools/effects subyacentes;
- cada skill declara required capabilities/environment y verification method;
- versiones conservan provenance y rollback;
- failure actualiza applicability, no borra ciegamente la skill.

## Preguntas/falsación

¿Qué loader/store/versioning ya existe? ¿Cómo evitar duplicar skills equivalentes? ¿Cuándo conviene una skill versus código/tool? ¿Cómo medir éxito sin autoevaluación circular? ¿Qué experiencias contienen secretos que no deben materializarse?

## Validation

Crear candidate desde una tarea repetida, validar por replay, usarla en una tarea nueva, medir ahorro/resultado, degradarla ante condición inválida y recuperar versión anterior.

## Definition of Done

ABOS puede crear/actualizar/deprecar una skill desde evidencia y reusarla con contracts y capabilities reales, sin confundir una narración procedural con una herramienta ejecutable.
