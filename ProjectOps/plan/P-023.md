## Objetivo

Antes de acciones relevantes, registrar qué outcome espera ABOS, con qué probabilidad/intervalo/condiciones cuando sea significativo; después observar realidad, comparar y actualizar beliefs, strategies, skills o estimadores.

## Loop canónico

OBSERVE → MODEL → PREDICT → ACT → MEASURE → COMPARE → ATTRIBUTE → LEARN → UPDATE.

No toda acción trivial necesita probabilidades formales; la profundidad es proporcional a riesgo/coste/irreversibilidad.

## Predicción mínima útil

Expected outcome, success criteria, time horizon, uncertainty, relevant costs, failure modes y assumptions. En dominios cuantificables puede incluir distribución/intervalos; en otros puede ser hipótesis cualitativa falsable.

## Learning

Distinguir execution failure, model error, stale assumption, capability mismatch, external change y measurement failure. Una mala predicción no se corrige automáticamente cambiando todos los parámetros; primero atribuir causa.

## Calibration

Cuando exista volumen y probabilities calibrables, medir calibration/brier/error por task class/model/strategy. No fabricar métricas sobre confidence `null`, scores cualitativos o muestras insuficientes.

## Auditoría resuelta

El repo ya contiene dos authorities que no deben duplicarse:

- `adaptive_paths`: prediction record estratégico persistente creado/seleccionado antes de la ejecución. Contiene hypothesis, assumptions, capabilities, environment/executor, sequence, expected outcome, expected cost y evidence refs.
- `adaptive_attempts`: outcome record posterior enlazado por `path_id`, con outcome, failure class/reason, observations/evidence, condition fingerprint, novelty, learned facts y retry eligibility.

Temporalidad runtime demostrada:

1. Planner produce path intent.
2. `AdaptivePathEngine.selectCandidate()` persiste/selecciona el path.
3. Orchestrator bindea tasks y sólo después ejecuta `dispatchAgentTask` o mensajería.
4. El resultado/exception posterior entra por `recordSuccess()` / `recordFailure()`.
5. Multi-task strategic path sólo se marca succeeded cuando todas sus tasks no superseded terminan.

Por tanto, crear `adaptive_predictions` o un segundo outcome ledger sería authority paralela.

Evidence Fabric conserva correlation/causation cross-domain; es el lugar correcto para un evento referencial de comparison/attribution, nunca para poseer canonical prediction/outcome state.

Skill Evolution conserva sus propias evaluations y lifecycle. Sólo recibe learning cuando existe una relación causal explícita con una `skillVersionId`; no se infiere por parecido de nombre/rol/capability.

## Defecto confirmado

`FailureClass` declara `unknown`, pero `classifyFailure()` actualmente usa `strategic_failure` como default para cualquier error no reconocido. Ese default es terminal, por lo que UNKNOWN puede convertirse en:

- outcome `failed`;
- path `failed`;
- invalidación del strategic belief;
- falsa atribución de model/strategy error.

Esto contradice este módulo y el invariante transversal `Unknown is first-class`.

## Hipótesis discriminadas

- H0 `NO_CHANGE`: FALSADA como loop completo; prediction/outcome/learning parcial ya existen, pero comparison/attribution explícito falta y UNKNOWN se clasifica incorrectamente.
- H1 `EXTEND_ADAPTIVE_INTELLIGENCE`: CONFIRMADA sólo para el delta mínimo sobre path/attempt existentes.
- H2 `EXTEND_EVIDENCE_FABRIC`: FALSADA como owner; CONFIRMADA como fabric causal/referencial.
- H3 `EXTEND_SKILL_EVOLUTION`: FALSADA como owner universal; CONFIRMADA como learning consumer sólo con skill-version causal explícita.
- H4 `COMPOSE_EXISTING_AUTHORITIES`: CONFIRMADA.
- H5 `CREATE_PARALLEL_PREDICTION_MANAGER`: RECHAZADA.

## Arquitectura decidida

1. REUSE `adaptive_paths` como prediction record previo.
2. REUSE `adaptive_attempts` como outcome record posterior.
3. Añadir comparison/attribution puro sobre path + attempt/diagnosis.
4. Emitir un Evidence Fabric event causal que referencie ambas authorities y describa `confirmed/contradicted/inconclusive` + attribution + learning target; no duplicar canonical values en otra tabla.
5. Corregir default classification a `unknown`; conservar matching explícito para evidencia real de strategic invalid result.
6. UNKNOWN debe persistir como attempt `inconclusive`, path `unknown` y nunca invalidar strategic belief por default.
7. Terminal contradiction sólo cuando la evidencia clasificada realmente la soporta.
8. Success intermedio de una ruta multi-task es progreso/inconclusive respecto del expected outcome estratégico; `completePath()` produce la confirmación terminal.
9. Existing learning permanece authority-local: assumptions, world belief/path, capability/environment/authorization opportunity/state según causalidad real.
10. No calcular calibration/Brier sin probabilities calibradas y muestra adecuada.

## Attribution semántica objetivo

- success terminal → `confirmed / none`;
- strategic failure / demonstrated impossible / prohibited route → `contradicted / model_or_strategy_error`;
- assumption invalid → `contradicted / stale_assumption`;
- capability missing → `inconclusive / capability_mismatch`;
- transient execution fault → `inconclusive / execution_failure`;
- environment/resource/authorization change → `inconclusive / external_condition`;
- unknown/unmeasurable evidence → `inconclusive / unknown_or_measurement`.

La taxonomía puede usar nombres internos más precisos siempre que preserve estas distinciones.

## Invariantes de validación

- prediction previa al outcome; no retrospective leakage;
- UNKNOWN/measurement failure no se convierte en failure inventado;
- attribution distingue execution/model/assumption/capability/external/measurement/unknown;
- learning actualiza sólo la authority causalmente responsable;
- restart conserva pairing mediante path/attempt IDs + Evidence causation;
- retry/reprocessing no duplica un learning terminal ya aplicado;
- calibration agregada sólo se publica con semántica y muestra suficientes;
- no se duplica world model, Evidence Fabric, Skill Evolution, task/path outcome ni memory authority;
- P-024/P-025 permanecen fuera de alcance salvo contexto estrictamente necesario.

## Validation requerida

- unknown/unmatched error → FailureClass `unknown`, attempt `inconclusive`, path `unknown`, belief no invalidado;
- explicit strategic invalid-result evidence continúa → strategic failure terminal;
- transient/capability/external conditions producen comparison `inconclusive` con attribution correcta;
- assumption invalid produce `contradicted/stale_assumption` y update sólo del assumption/related strategic state;
- terminal strategic contradiction produce `contradicted/model_or_strategy_error` e invalidación existente;
- single-task/final path success produce `confirmed`;
- multi-task intermediate success no confirma prematuramente el strategic expected outcome;

- restart/reopen conserva evidence pairing;
