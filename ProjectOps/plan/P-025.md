## Objetivo

Reemplazar review/consensus nominal y planning excesivamente lexical por un ciclo estratégico basado en objetivos, compromisos, alternatives, beliefs, evidence, expected value, uncertainty, capabilities, environment, cost, contingencies y failure recovery, preservando Adaptive Path como autoridad de rutas.

P-025 debe convertir el principio `CAPABILITY_PRESERVATION_BEFORE_RESTRICTION` en juicio operativo general: cuando una capacidad legítima presenta riesgo, ABOS debe intentar gobernarla mediante mejor razonamiento y evidencia antes de eliminarla o escalarla innecesariamente a un humano.

## Estado observado

La auditoría encontró paths de `plan-mode` donde auto/consensus pueden aprobar de forma placeholder incluso bajo condiciones que deberían exigir revisión real. P-010 además demostró el caso inverso: un riesgo real puede terminar convertido en restricción/creator approval aunque la capacidad sea legítima. Ambos extremos deben reauditarse antes de modificar.

## Cognitive protocol objetivo

**DEFINE objective/commitment → decompose required outcomes → identify available/missing resources → interrogate assumptions → generate materially distinct paths → pre-mortem (“si falla, ¿por qué?”) → estimate evidence/value/cost/risk/liquidity/contingency → simulate/probe cuando aporte información → choose → execute one explicit boundary → observe → compare prediction vs outcome → update world model → replan.**

La decisión no se limita a “¿puedo hacer X?”. Debe incluir, cuando aplique:
- qué más hace falta para cumplir completamente el compromiso;
- qué ya existe y puede reutilizarse;
- qué debe adquirirse ahora y qué puede esperar;
- qué dependencia puede fallar y cuál sería la ruta de reemplazo;
- qué compromiso futuro cambia materialmente la decisión actual;
- qué evidencia justificaría gastar más, menos, esperar o cambiar de ruta.

## Review

Approval no puede ser constante. Review debe producir critique/evidence/conditions; consensus sólo existe si múltiples evaluadores/criterios reales lo sustentan, o se elimina ese claim. El usuario puede fijar modo manual/adaptive según riesgo.

Human review no es el fallback universal de una decisión difícil. Se escala cuando existe `REAL_BOUNDARY` o oversight manual explícito; `GOVERNABLE_RISK` debe resolverse autónomamente cuando ABOS posee autoridad y evidencia suficientes.

## Capability/Judgment gate

Antes de recomendar retirar, desactivar o human-gate una capability:
1. clasificar `REAL_BOUNDARY | GOVERNABLE_RISK | IMMATURE_CAPABILITY | REDUNDANT_OR_HARMFUL | UNKNOWN`;
2. evaluar al menos una ruta que preserve la capacidad;
3. demostrar por qué contexto/judgment/verificación/observabilidad/adaptation no bastan, si aun así se restringe;
4. registrar qué nueva información permitiría relajar una guard provisional.

## Adaptive Path invariants

Objective != method; equivalent failed path no se repite sin material change; auth/prohibition no se evade; capability gap usa P-017; environment failure scoped; UNKNOWN preservado; una desviación de coste/histórico es evidence para revisar, no una prohibición automática.

## Ataques

Plan atractivo pero capability inexistente, estimate falso, ruta equivalente renombrada, infinite replanning, local optimum, approval circular, high-cost plan con low-cost probe disponible, stale belief, gasto históricamente anómalo con causa legítima, gasto pequeño sin valor, capability legítima eliminada por comodidad, creator approval usado para sustituir juicio interno.

## Definition of Done

Una decisión compleja produce alternatives y motivos discriminantes, descompone el resultado comprometido en necesidades/dependencias, review real, pre-mortem/falsación proporcional al riesgo y replanning basado en evidence; distingue frontera real de riesgo gobernable; puede justificar causalmente una decisión extraordinaria sin depender de thresholds fijos; tests ya no codifican ni autoaprobación ficticia ni human-gating ficticio como PASS.
