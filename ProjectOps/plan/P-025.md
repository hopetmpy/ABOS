## Objetivo

Reemplazar review/consensus nominal y planning excesivamente lexical por un ciclo estratégico basado en objetivos, alternatives, beliefs, evidence, expected value, uncertainty, capabilities, environment, cost y failure recovery, preservando Adaptive Path como autoridad de rutas.

## Estado observado

La auditoría encontró paths de `plan-mode` donde auto/consensus pueden aprobar de forma placeholder incluso bajo condiciones que deberían exigir revisión real. Debe reauditarse el código exacto y tests antes de modificar.

## Cognitive protocol objetivo

DEFINE objective → interrogate assumptions → generate materially distinct paths → pre-mortem (“si falla, ¿por qué?”) → estimate evidence/value/cost/risk → simulate/probe cuando aporte información → choose → execute one explicit boundary → observe → update world model → replan.

## Review

Approval no puede ser constante. Review debe producir critique/evidence/conditions; consensus sólo existe si múltiples evaluadores/criterios reales lo sustentan, o se elimina ese claim. El usuario puede fijar modo manual/adaptive según riesgo.

## Adaptive Path invariants

Objective != method; equivalent failed path no se repite sin material change; auth/prohibition no se evade; capability gap usa P-017; environment failure scoped; UNKNOWN preservado.

## Ataques

Plan atractivo pero capability inexistente, estimate falso, ruta equivalente renombrada, infinite replanning, local optimum, approval circular, high-cost plan con low-cost probe disponible, stale belief.

## Definition of Done

Una decisión compleja produce alternatives y motivos discriminantes, review real, pre-mortem/falsación proporcional al riesgo y replanning basado en evidence; tests ya no codifican una autoaprobación ficticia como PASS.
