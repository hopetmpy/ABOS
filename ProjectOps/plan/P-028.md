# P-028 — Implementar delegation por competencia, evidencia y coste

## Objetivo

Reemplazar asignación rígida por roles/departments o “primer child idle” por selección basada en capacidad real, experiencia, outcome evidence, availability, environment, coste, latency, trust/authority y task requirements.

## Arquitectura objetivo

Agent/worker/child competence profile derivado de verified capabilities, skills, outcome history, environment access y constraints. Task requirements se comparan contra profiles; UNKNOWN permanece penalizado/indeterminado según riesgo, no false.

Roles pueden existir como etiquetas/hints humanos, no como universo cerrado ni sustituto de capability matching.

## Reglas

- parent no presta autoridad del child ni viceversa;
- performance histórico se contextualiza por task class;
- coste esperado incluye inference/environment y coordination overhead;
- delegation puede decidir ejecutar localmente si es mejor;
- failure actualiza competence evidence, no etiqueta permanente de incapacidad.

## Validation

Tasks con candidatos heterogéneos, candidate unavailable, stale competence, high-cost specialist, new agent unknown, failure/reassignment y restart.

## Definition of Done

ABOS puede explicar por qué delegó una tarea a un actor concreto usando requirements/evidence/cost/authority, y tests demuestran que no depende de una lista fija de roles ni del orden de registro.
