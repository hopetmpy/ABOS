## Objetivo

Asegurar que un child nace con runtime/identity/constitution/context mínimos verificados, hereda conocimiento/capabilities/skills de forma selectiva y trazable, y mantiene autoridad/wallet/state propios.

## Estado observado

Spawn actual posee buenas piezas: wallet, sandbox, lifecycle y propagation hash. La auditoría detectó que constitution propagation puede ser best-effort y que `verifyConstitution()` no debe asumirse gate sólo por existir. Debe reauditarse el flujo completo.

## Birth gate objetivo

Sandbox/resource ready → runtime installed/built → identity/wallet verified → constitution materialized + hash/semantic gate → genesis/parent relation persisted → minimum cognitive index/skill catalog inherited → runtime start → post-start health. Un fallo material bloquea `operational/healthy` y deja evidence/recovery path.

## Family Knowledge

Children no reciben todo el episodic history del parent. Heredan constitution, family identity, knowledge index/summaries relevantes, verified skill/capability catalog, shared lessons y query route; deep/raw memory se solicita por necesidad/authority.

## Invariantes

- child wallet/identity sovereign;
- parent cannot fake child debit/health;
- constitution failure no se traga como non-critical;
- selective inheritance evita prompt/state explosion y leakage;
- lineage/version/provenance persistentes.

## Validation

Birth success, constitution mismatch/missing, build fail, wallet parse fail, restart before healthy, selective knowledge query, child offline y lineage recovery.

## Definition of Done

Un child no entra en estado operativo sin bootstrap comprobado; puede consultar conocimiento familiar sin copiar todo el parent y conserva separación de identidad/authority/state.
