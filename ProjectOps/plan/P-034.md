## Objetivo

Asumir que ABOS fallará y demostrar que preserva identidad, autoridad, idempotencia, evidencia y economía cuando procesos mueren, providers fallan, timeouts dejan trabajo vivo o el runtime reinicia.

## Fault classes

Crash entre effect/persist; network partition; late success; duplicate delivery; provider rate limit/outage; auth expiry; disk/db error; child unreachable; MCP crash; browser crash; self-mod build/activation failure; task timeout; stale lease; corrupted non-secret config/state fixture; budget exhaustion.

## Reglas

Cada injection debe tener expected invariant y recovery evidence. Un retry no puede solaparse con side effect previo desconocido. Recovery no puede transformar UNKNOWN en success/failure inventado.

## Sustained operation

Soak/restart tests sobre tareas/heartbeat/memory/capabilities/economics durante una ventana suficiente para detectar leaks, stale state, retry storms y evidence drift. E7 sólo se reclama cuando la duración/condiciones reales lo justifican.

## Definition of Done

Los fault scenarios críticos producen estados recuperables/explicables sin corrupción ni efectos duplicados conocidos; sustained run alcanza el nivel de evidencia que se declare, sin promocionarlo artificialmente a LIVE externo.
