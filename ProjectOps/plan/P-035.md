# P-035 — Retirar stubs, duplicados y autoridades legacy después de integración

State: PLANIFICADO
Priority: ALTA

Required-Context:
- `AGENTS.md`
- `ProjectOps/PROJECT.md`
- `src/`
- `src/__tests__/`
- `ARCHITECTURE.md`
- `README.md`

Dependencies: P-008..P-034 materialmente aplicables. Debe ejecutarse después de que la autoridad reemplazante esté integrada y validada.

## Objetivo

Eliminar deuda que ya no aporta capacidad: executors nominales, branches internas legacy, registries paralelos, code paths desconectados, comments/prompts overclaiming, tests que fijan semántica vieja y adapters duplicados, preservando cualquier valor antes de retirar.

## Regla de decisión

Stub/incomplete → primero preguntar si capability necesaria. Si sí: completar/integrar en su P correspondiente. Si no/duplicado/contradictorio: retirar sólo cuando reemplazo/authority y migration estén demostrados.

## Auditoría

Repetir full tracked-file inventory/import graph, unreachable source review, TODO/FIXME/stub scan, duplicate semantic authorities, obsolete config/schema compatibility, dead tests y docs references. Static unreachable no equivale automáticamente dead code; loaders/plugins/CLI entrypoints requieren análisis.

## Invariantes

- no eliminar compatibilidad necesaria sin migration;
- history/audit preserved by Git;
- no romper public package/CLI exports;
- no borrar future extension point sólo porque hoy tenga un provider;
- tests se actualizan por semántica correcta, no para esconder failures.

## Definition of Done

Cada pieza productiva queda clasificada como authority/active extension/compatibility/future extension o retirada con razón; no quedan stubs conocidos que el runtime anuncie como capacidad real ni autoridades paralelas injustificadas.
