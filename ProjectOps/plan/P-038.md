## Origen y problema

El roadmap ABOS previo a P-007 contenía un `Open Knowledge Graph` separado de Context Activation y Branching Memory: conocimiento extensible con entidades/relaciones, provenance/confidence y expansión relacional. P-007 compactó knowledge dentro de P-020 y world beliefs dentro de P-022 sin dejar equivalencia explícita.

La auditoría de 2026-09-24 encontró:
- `KnowledgeStore` actual es open-world en categorías, pero persiste principalmente `category/key/content/source/confidence/...` y ofrece lookup/search;
- `relationship.ts` conserva memoria de relaciones con entidades/agentes, no un grafo general de conocimiento;
- P-022 posee facts/beliefs falsables y Evidence Fabric aporta correlation/provenance;
- no se demostró una authority actual para entity/relation/edge identity, traversal/expansion y relación semántica general entre knowledge items.

Esto se clasifica `MISSING/UNPROVEN` respecto del objetivo histórico, no como prueba de que sea necesaria una base de datos de grafos nueva.

## Objetivo

Auditar si el contrato histórico de Open Knowledge Graph ya puede expresarse coherentemente mediante KnowledgeStore + semantic/relationship memory + World Model/Evidence Fabric. Si no, extender/unificar esas authorities para representar conocimiento relacional abierto y navegable sin crear una memoria paralela ni duplicar world-model truth.

## Auditoría previa obligatoria

1. Mapear `knowledge_store`, semantic memory, relationship memory, ingestion/retrieval, Evidence Fabric y P-022 facts/beliefs.
2. Identificar producers/consumers que realmente necesitan relaciones explícitas versus simple retrieval textual.
3. Buscar cualquier entity/relation/edge schema o projection ya existente bajo otro nombre.
4. Separar cuidadosamente:
   - knowledge fact/content;
   - relation/edge;
   - belief/hypothesis;
   - evidence/provenance;
   - relationship/social memory.
5. Auditar persistence, indexing, dedup/version/conflict, restart y migration.
6. Comparar `NO_CHANGE | EXTEND | UNIFY | ADDITIVE_RELATIONAL_PROJECTION | CREATE`; una graph database dedicada no se presume.

## Semántica objetivo

Cuando exista evidencia de utilidad, la architecture debe soportar de forma abierta:
- entity identity extensible;
- typed or described relations sin taxonomy universal cerrada;
- provenance/evidence/confidence por node/relation cuando corresponda;
- temporal/version semantics cuando un hecho o relación cambie;
- traversal/neighbor expansion bounded por query/context budget;
- enlaces desde facts/beliefs/memory sin convertir el graph en segunda authority de esos dominios;
- merge/dedup/conflict explícito;
- query y activation útiles al agent loop/strategic cognition.

## Invariantes

- no segunda memory authority;
- graph relation != belief truth;
- inferred edge != observed fact;
- relation stale/unknown permanece explícita;
- open-world significa extensible, no ausencia de provenance/authority;
- un graph index/projection derivado puede reconstruirse de su source cuando esa sea la decisión; no se promociona a primary truth por conveniencia;
- no cargar el grafo completo al prompt.

## Fallos/adversarial

Entity alias collision, duplicate edges, cycles, graph explosion, stale relation, inferred-as-observed contamination, provenance loss, deleted source still referenced, restart/migration partial, unbounded traversal, malicious external knowledge linking itself to trusted entities.

## Validación

Si hay implementación nueva/extensión:
- persist/restart de entities/relations;
- dedup/conflict/version tests;
- bounded traversal/activation;
- provenance propagation;
- separación facts/beliefs/inferences;
- integración con retrieval/context sin prompt explosion;
- migration/recovery y compatibility con P-020/P-022.

Si la auditoría demuestra equivalencia suficiente en source actual, cerrar `NO_CHANGE` sólo con mapping y evidencia ejecutable, no por similitud nominal.

## Definition of Done

La intención histórica de Open Knowledge Graph queda trazablemente resuelta: o existe equivalencia demostrada sobre authorities actuales, o ABOS dispone de una capa relacional abierta, persistente y navegable que preserva provenance/confidence/temporalidad y se integra con Cognitive Fabric/World Model sin duplicar sus truths.
